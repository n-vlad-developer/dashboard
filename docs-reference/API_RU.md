# API кабинета Q1 v7

База: `/api/dashboard/`. Все URL с завершающим `/`. HTTPS, JSON UTF-8. Даты ISO 8601, длительности в секундах, деньги — decimal-строки. Для файлов — multipart/form-data. Пагинация списков: `?page=1`, по 50, ответ `{count,next,previous,results}`.

## Авторизация и права

| Метод | Путь | Тело / результат |
|---|---|---|
| POST | auth/login/ | `{email,password}` → `{access,refresh}` |
| POST | auth/refresh/ | `{refresh}` → `{access}` |
| POST | auth/logout/ | Отзывает текущую сессию, 204 |
| GET | me/ | id, email, full_name, venues с permissions и translation_limits |

Пароль тот же, что в мобильном приложении. Access живёт 15 минут, refresh и серверная сессия — 7 дней. Заголовок `Authorization: Bearer <access>`. Для refresh access не нужен. Выход отзывает оба токена этой сессии, смена пароля делает её недействительной. Новая сессия не отзывает другие устройства. Не хранить пароли в клиенте; схему безопасного хранения токенов выбирает фронтенд (например, BFF с HttpOnly-cookie).

Доступ только активным admin/director с активной сетью и заведением. Проверки выполняются на сервере при каждом запросе; выключение кабинета применяется к уже выданным токенам. Директор видит только allowed_point_of_sales своей сети; admin — свой point_of_sale. Наличие is_staff или superuser само по себе не заменяет профиль сотрудника для входа в кабинет. Главная Django-админка остаётся отдельной.

`me.venues[].permissions`: menu, analytics, translation. Показывать разделы по этим флагам. Отдельные флаги director/admin задаёт владелец платформы в главной админке. Кабинет не может повышать себе права, менять лимиты или включать AI-импорт.

## Меню

Префикс всех следующих путей: `venues/{venue_id}/`.

| Ресурс | Связь при создании | Содержимое |
|---|---|---|
| menus | Заведение берётся из URL | Название, валюта, доступность, порядок, рекомендации |
| categories | menu | RU/KK/EN, описание, обложка, порядок, рекомендации |
| items | menu, category | Поля блюда, цены, вес, языки, изображение, флаги |
| modifier-groups | menu_item | Группы модификаторов и ограничения выбора |
| modifiers | group | Модификаторы, переводы, цены, доступность |
| synonyms | menu_item | Язык, поисковая фраза, активность |

Для каждого ресурса:

- `GET {resource}/` — список (активные и выключенные).
- `GET {resource}/{id}/` — объект со всеми открытыми полями.
- `POST {resource}/` — создание, 201.
- `PATCH {resource}/{id}/` — частичное изменение, 200.
- DELETE и PUT не поддерживаются, 405. Выключение через `is_active=false`; для QR-доступности — соответствующий существующий флаг модели.

Фильтры списков: menu, category, menu_item, group — для тех ресурсов, где поле существует. Например `items/?menu=12&category=30`. Все связи проверяются по сети и заведению; блюдо и категория должны быть одного меню. Родитель существующей записи (menu/menu_item/group) не переносится через PATCH; категория блюда может меняться внутри меню.

`GET schema/` возвращает точный перечень полей, типы, required, read_only, ограничения и choices. Статическая копия — menu-fields.json. Все бизнес-поля моделей включены; tenant/point_of_sale назначает сервер, source/external_id/created_at/updated_at — только чтение, raw_data внешней системы не выдаётся. Передача защищённых или неизвестных полей возвращает 400. Меню iiko/других внешних источников по умолчанию нельзя изменять; исключение включает главная админка. Синхронизация может перезаписать ручные правки.

### Защита от потери правок

Для PATCH обязателен `If-Match: <updated_at>` из последнего GET/POST/PATCH этого объекта. При несовпадении — 409; повторно загрузить объект и предложить пользователю объединить изменения. Не отправлять GET-объект целиком: передавать только изменённые записываемые поля.

```http
PATCH /api/dashboard/venues/2/items/18/
Authorization: Bearer ACCESS
If-Match: 2026-11-06T12:10:00+05:00
Content-Type: application/json

{"price":"3500.00","is_active":true,"name_ru":"Чай с облепихой"}
```

Использовать точную строку updated_at сервера, а не самостоятельно сформированный timestamp. При изменении картинки передать файл `image` через multipart с тем же If-Match. JPEG/PNG/WEBP до 10 МБ; для удаления картинки — JSON `image:null`, если поле допускает null. Поля/nullable сверять со schema. Пустая строка image допустима только если её принимает текущий сериализатор; не отправлять URL файла как загружаемое изображение.

### AI-перевод

`POST menus/{id}/translate/`, пустое JSON-тело, обязательный `Idempotency-Key` (до 48 символов). Переводит только пустые языковые поля категорий, блюд, групп и модификаторов в RU/KK/EN. Существующие переводы не затирает; меню без пустых полей возвращает translated=0.

202 → `{id,status,reserved_chars}`. Повтор с тем же ключом и тем же меню возвращает то же задание. Использование ключа для другого меню — 409. Статус читать через jobs/{id}/.

Месячные лимиты общие на заведение: число заданий и символы исходника × число целевых языков. Месяц определяется в UTC. Резерв списывается при создании; неуспешные задания тоже учитываются, чтобы повторные ошибки не тратили бюджет бесконтрольно. До 2000 символов в одном исходном поле и до 12000 взвешенных символов за запуск. Это лимит объёма, не точный денежный/token-бюджет OpenAI. До 4000 выходных токенов на пакет из пяти полей. Повторных платных попыток автоматически нет. При ошибке уже выполненные пакеты сохранены. Редактирование исходника во время перевода останавливает конфликтующий пакет.

AI-создание меню, генерация изображений и импорт документов в кабинет не открыты. Они остаются функциями главной админки.

## Аналитика, отчёты, история

| Метод | Путь после venues/{id}/ | Назначение |
|---|---|---|
| GET | analytics/?start=2026-11-01&end=2026-11-07&granularity=day | Готовые карточки, графики, разрезы; end исключительно |
| GET | reports/ | Список суточных отчётов, версия и дата расчёта |
| GET | reports/{report_id}/ | Полный payload одного дня |
| POST | reports/ | `{start:"2026-11-01",end:"2026-11-06"}`; end **включительно**, до 366 дней; 202 с id задания |
| GET | jobs/ | Доступные по правам задания заведения |
| GET | jobs/{job_id}/ | kind, status, processed, total, error, created_at |
| GET | calls/ и calls/{call_id}/ | История вызовов, участники и снимки |
| GET | shifts/ и shifts/{shift_id}/ | Смены и показатели сотрудников |
| GET | schema/ | Поля меню для построения форм |

Все аналитические пути требуют analytics=true; задания перевода требуют translation=true. Списки calls/shifts поддерживают start (включительно), end (исключительно) в локальном часовом поясе заведения и staff_id. Для calls это принимающий сотрудник, для shifts — владелец смены. Calls также принимает status=created/arrived/closed/auto_closed/expired. Просрочка после закрытия отражена в was_expired, поэтому фильтр status=expired показывает только ещё не принятые просроченные вызовы.

Calls: created_at, accepted_at, closed_at, status, was_expired, expired_at, accepted_by, closed_by, shift_id, table_id, category_id, staff_at_creation, timing, history_complete. status=arrived отображать как «Принят». Закрыт/закрыт системой можно объединить в интерфейсе; машинный статус сохраняется. Для старых данных history_complete=false.

Shifts: staff_id, opened_at, closed_at, closed_source, work_seconds, accepted_calls, closed_calls (включая автоматические), accepted_expired_calls, acceptance_avg_seconds, acceptance_median_seconds, acceptance_p90_seconds, accepted_per_hour. Вызовы учитываются только при совпадении смены и принявшего сотрудника. API смен отображает собственную продолжительность каждой смены; общая аналитика устраняет пересечения смен одного сотрудника.

Задания: queued → running → completed/failed. Один активный пересчёт на заведение; повтор — 409. Для переводов дополнительно действует ключ идемпотентности и месячная квота. Общий пересчёт доступен только главной админке, не через кабинет. Опрос jobs раз в 3–5 секунд достаточен; фоновые обновления данных — раз в 10 минут. Не считать missing-день нулевым — правила в ANALYTICS_RU.md.

## Ошибки и подключение фронтенда

400 — неверное тело/фильтр/связи; 401 — недействительная сессия; 403 — роль/право/лимит; 404 — объект отсутствует или недоступен; 405 — неподдерживаемый метод; 409 — конфликт версии/повторное задание; 429 — ограничение входа (10 попыток/минуту на IP); 503 — неверный timezone при запросе аналитики. Общая ошибка обычно `{detail:...}`, ошибки полей — словарь полей.

Последовательность: login → me → выбор доступного заведения → schema и списки меню → analytics. После 401 один refresh, затем повтор исходного запроса; при отказе refresh — экран входа. После 403/404 обновить me. Для PATCH сохранять updated_at из ответа. Для AI сохранять idempotency-key до получения задания. Периодические отчёты и графики отдавать без клиентского пересчёта формул.

Postman-коллекция содержит шаблоны запросов и автоматическое сохранение access/refresh после входа. Значения email/password заполнять локально; в архиве секретов нет. Фронтенд, экспорт PDF/XLSX, управление сотрудниками, настройками заведения и отдельная бизнес-дата ресторанного дня этим API не реализуются: настройки остаются в главной админке, аналитика группируется по календарным дням заведения.
