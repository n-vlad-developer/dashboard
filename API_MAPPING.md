## Функции, которые требуют дальнейшей проверки/доработки

- Точное представление получасового графика зависит от ответа живого сервера; показание по дням готово, переключатель детализации присутствует.
- `schema` содержит поля типа `field`; для многозначных связей формы пока принимают ID или JSON. Для production-UX их лучше превратить в селекторы связанных объектов после проверки структуры сериализаторов.
- При изменении изображения используется multipart; серверное ограничение до 10 МБ описано в подсказке, полноценная валидация предпросмотра/кропа ещё не реализована.
- Демо-данные не соответствуют рабочим значениям и не доказывают успешную интеграцию с API.
- `me.venues[].translation_limits` как точная структура не приведена в документах. Значит, UI не подставляет из головы числа доступной квоты.
- Пагинация работает по 50 объектов и локальный поиск фильтрует только текущую страницу, а не выполняет неописанный серверный поиск.
- Только административный Django интерфейс: управление персоналом, расписанием, лимитами и правами, AI-импорт меню, генерация изображений, общий пересчёт.
- API не содержит готового экспорта PDF/XLSX — кнопки экспорта не имитируются.

## Что особенно важно при просмотре графиков

1. `summary` может быть `null`; пропуски `state=missing` нельзя рисовать как нули.
2. `freshness.available_days / expected_days` нужно показывать пользователю.
3. Классы `closed`, `expired`, `arrived` могут пересекаться; круговую диаграмму на них не строить.
4. `series` отражает дату создания вызова, а не дату закрытия.
5. `guest.noncancelled_amount` и `orders.paid_closed_amount` — разные источники, не суммируются.
6. `accepted_expired_calls` не обвиняет принимающего сотрудника.
7. `shift.work_seconds` не означает эффективное время обслуживания; перерывы неизвестны.
8. Ни посещения уникальных гостей, ни загрузка столов по проценту в API не подтверждаются.
