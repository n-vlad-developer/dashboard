# Q1 Dashboard

React / Next.js кабинет заведения. `/dashboard` и `/demo` используют один компонент `Dashboard`, общую навигацию, редакторы, фильтры, таблицы и кнопки. Демо подменяет только транспорт данных, не интерфейс.

## Запуск

Требуется Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Демо: http://localhost:3000/demo. Для демо секрет и подключение к серверу не нужны.

Для реального входа скопируйте `.env.example` в `.env.local`. Укажите `Q1_API_BASE_URL`, публичный `APP_ORIGIN` и уникальный `SESSION_SECRET`. Сгенерировать секрет:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

При локальном входе `APP_ORIGIN` должен совпадать с адресом браузера (например, `http://localhost:3000`). В production укажите HTTPS-адрес кабинета. Если раньше использовался секрет из старого примера, его необходимо заменить: он больше не принимается. Это завершит старые сессии.

```sh
npm run build
npm start
```

## Структура

- `app/` — маршруты, метаданные, loading/error/not-found, серверные API.
- `components/layout/` — навигация и переключение заведений.
- `components/brand/` — оригинальная анимированная загрузка Q1.
- `components/feedback/` — общий экран ошибок Q1 с иллюстрацией.
- `components/DateField.tsx`, `ResponsiveTable.tsx` — общие адаптивные React-компоненты.
- `lib/client.ts` — единая точка запросов; рабочий API и демо разделены по маршруту.
- `lib/demo*.ts` — синтетические данные, изменения и экспорт демо.
- `lib/session.ts`, `server.ts`, `request-body.ts`, `proxy.ts` — серверная сессия, API и защита запросов.
- `styles/` — базовый интерфейс, вход и единая палитра `design-system.css`.
- `public/brand/` — оригинальные иконки Q1, Apple touch icon, социальная обложка.
- `tests/` — контракты данных/API и браузерные сценарии.
- `docs-reference/` — исходная документация предоставленного API.

## Демо

Все значения синтетические. Создание и изменение меню, фильтры, переводы, отчёты, повтор задания и экспорт доступны через те же элементы интерфейса. Обработка заданий в демо моделируется немедленно; реальные задания выполняет сервер. Переводы — демонстрационные заполнители, не результат внешнего AI-сервиса.

Изменения изолированы по заведению и сохраняются в `sessionStorage` текущей вкладки. При запрете/переполнении хранилища используется память до перезагрузки; это особенно касается крупных изображений. Демо никогда не отправляет запросы к рабочему API и не меняет авторизованную сессию. Сброс демо: очистить данные сайта или открыть новую независимую вкладку.

## Проверки

```sh
npx playwright install chromium webkit
npm test
npm run typecheck
npm run build
npm audit
npm run test:auth
```

Тесты сами запускают локальный сервер, если его ещё нет. Дополнительно: `npx playwright install firefox`, затем `npm run test:firefox`.

`test:auth` отдельно поднимает production-сборку и изолированный тестовый API: проверяет OTP, сохранение зашифрованной HttpOnly-cookie, доступ в кабинет, профиль, обновление токенов и выход. Письма и запросы в рабочий Q1 API не отправляются. Также проверяется отказ до отправки/использования кода при отсутствующем `SESSION_SECRET`.

Если код приходит, но появляется «Не удалось завершить авторизацию», проверьте настройку `SESSION_SECRET` в окружении сервера. Ключ из локального `.env.local` не включается в Git или архив: при развёртывании задайте отдельный постоянный случайный ключ и перезапустите сервер. Новый код нужно запросить после исправления: предыдущий мог быть уже использован бэкендом.

Используются Chromium и WebKit, ширины 320/390/768/1440 px. WebKit на Windows не заменяет проверку на физическом Mac/iPhone. Текущий отчёт: [docs/VALIDATION_RU.md](docs/VALIDATION_RU.md).
