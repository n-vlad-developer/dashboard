# Q1 Dashboard · MindTech

Первый исполняемый фронтенд кабинета Q1 по документации API v7. Реализация на **Next.js 16 + React 19 + TypeScript**, без изменений существующего Django backend.

> **Статус:** рабочий исходный фронтенд с BFF и синтетическим демо-режимом. Доступ к рабочему API, JWT, CORS, реальные роли и ответы PostgreSQL не проверены. Для production нужен staging-прогон. Статический `preview.html` предназначен только для визуального просмотра главного экрана, без API.

## Запуск в Windows PowerShell

```powershell
cd C:\path\to\q1-dashboard
Copy-Item .env.example .env.local
# Отредактировать .env.local: ОБЯЗАТЕЛЬНО задать собственный SESSION_SECRET
npm install
npm run dev
```

Открыть `http://localhost:3000`.

Чтобы сгенерировать секрет:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Для визуальной демонстрации оставьте `NEXT_PUBLIC_DEMO_MODE=true`. На экране входа появится кнопка «Открыть демонстрацию». **Все данные демо синтетические, запись и перевод отключены.** Для работы с сервером установите `NEXT_PUBLIC_DEMO_MODE=false` и проверьте `Q1_API_BASE_URL`.

Если `npm install` на машине требует доступа к интернету, установите зависимости обычным способом из npm. В подготовительной среде Next.js и React не были установлены, поэтому production-сборка `next build` здесь не запускалась; TypeScript/TSX проверены на синтаксис.

## Визуальная система

Дизайн ориентируется на продуктовый подход `https://guest.mindtech.kz/`: крупные заголовки, компактные блоки, бренд Q1, единая структура продукта «гость/персонал/руководитель». Исходную страницу удалось открыть и изучить по структуре/содержанию, **но её таблицы стилей и точные HEX не были доступны**. Поэтому значения ниже — авторский стартовый вариант, не заявка на точное извлечение палитры:

- `--primary: #7464f7` — лиловый акцент;
- `--mint: #c8ff9e` — светло-лаймовый знак;
- `--sidebar: #171b2b` — глубокая тёмная навигация;
- `--soft: #f6f7fb` — светлая рабочая поверхность;
- `--ink: #202434` — основной текст.

Цвета находятся в `app/globals.css` в начале файла и заменяются централизованно после визуальной сверки со скриншотами оригинального сайта. Предусмотрены мобильные стили и адаптивная навигация.

## Основные страницы

1. **Обзор** — `summary`, `freshness`, `categories`, `staff`, `guest`. Никакой выдуманной загрузки столов или «оценки официанта».
2. **Аналитика** — динамика вызовов и гостевых заказов, сотрудники, столы, жалобы, климат, контроль качества; `null` отображается как «—», missing не превращается в 0.
3. **Меню** — шесть связанных ресурсов (`menus`, `categories`, `items`, `modifier-groups`, `modifiers`, `synonyms`), формы динамически строятся из серверного `/schema/`, PATCH только изменённые поля + точный `If-Match`.
4. **История вызовов** — статусы `created`, `arrived` (подпись «Принят»), `closed`, `auto_closed`, `expired`; дополнительное указание `was_expired`, историческая неполнота.
5. **Смены** — история смен и время принятия; данные без «рейтинга качества».
6. **Отчёты** — просмотр суточных отчётов, POST диапазона до 366 дней, где `end` включается.
7. **Фоновые задания** — статусы queued / running / completed / failed, обновление каждые 5 секунд только на активной вкладке.

Вся навигация фильтруется по `me.venues[].permissions`. Флаги и лимиты редактируются только в основной Django Admin.

## Авторизация и безопасность

- `/api/auth/login` проксирует вход и сохраняет access+refresh внутри **AES-256-GCM зашифрованной HttpOnly, SameSite=Lax cookie**; JS в браузере не получает JWT и пароль нигде не сохраняется.
- `/api/q1/[...path]` — ограниченный серверный BFF-прокси к `Q1_API_BASE_URL`. Запросы получают Bearer на сервере; при 401 ровно один refresh и один повтор запроса.
- `/api/auth/logout` отзывает сессию на сервере (по контракту) и удаляет локальную cookie.
- GET, POST, PATCH в рамках allowlist; произвольные URL, DELETE и PUT не проксируются.
- Сервер обязан продолжать проверять права и доступ к чужим заведениям на каждом запросе. UI скрывает разделы, но не является механизмом защиты.
- В production секрет и HTTPS обязательны; рекомендуется собственный домен кабинета и проверка лимита cookie/JWT у реальных пользователей.

## Важные нюансы из контрактов

- Даты аналитики: `start` включительно, `end` **исключительно**; `half_hour` только до 7 дней. Дата конца отчётов POST — **включительно**.
- Пагинация 50 записей; интерфейс листает серверные страницы.
- Поля меню: `POST` создание, `PATCH` изменение; никакого DELETE/PUT. `is_active=false` отключает запись. Доступность блюда (`is_available`) и меню для гостя (`is_qr_available`) не идентичны.
- Для картинки multipart с `If-Match`, до 10 МБ; проверка формата/размера пока выполняется главным образом API, а не формой.
- `409` не перезаписываем силой: предлагаем заново загрузить объект. Для перевода `Idempotency-Key` сохраняется в `sessionStorage` до подтверждения создания задания (это **не** токен авторизации).
- Суммы `guest.noncancelled_amount` и `orders.paid_closed_amount` не складываются; валюта гостевых заказов не проставляется, пока её не задаст подтверждённая настройка.
- Сессии гостей не уникальные люди; нет событий просмотра меню и конверсии кликов.
- При `freshness.complete=false` явное предупреждение; текущий день может быть `partial`. `comparison` не используются без `comparable=true`.
- Автоматические закрытия не означают подтверждённого обслуживания; просрочка может пересекаться с принятием и закрытием.

## Где что лежит

```text
app/                 Next App Router (login, dashboard, BFF auth & proxy)
components/          Полный UI: обзор, аналитика, меню, история, отчёты
lib/session.ts       Шифрование серверной сессии
lib/server.ts        Backend URL + server fetch
lib/mock.ts          Синтетические ответы API для demo
lib/menu-fields.json Статическая копия официальной схемы (для demo)
app/globals.css      Дизайн-токены, адаптивный стиль
preview.html         Автономный предпросмотр главного экрана
preview.css          CSS предпросмотра без внешних шрифтов
.env.example         Образец переменных окружения без секретов
```

## Перед production / доработка

Обязательно провести интеграционное тестирование на staging с действующими ролями admin/director, `me` и пагинацией, файлами/связанными полями, действительными payloads вызовов/смен, CORS/HTTPS, ошибками 403/404/409/429, неполными отчётами и переводами по квоте. Проверить отображение разных локалей UI (сейчас интерфейс на русском, хотя редактируются языки RU/KZ/EN) и доступность форм. Уточнить точные цвета/шрифты с исходного `guest.mindtech.kz` через исходный CSS или эталонные скриншоты.

Новые endpoints для управления сотрудниками, расписанием, POS, QR-печатью, экспорта PDF/XLSX **не придумывались**: текущая документация их не предоставляет. Для этого нужны отдельные API и согласование с бэкендом.
